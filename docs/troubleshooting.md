# Если что-то не работает

## Быстрая диагностика

```sh
python scripts/verify-skill.py      # ждём: scout check: OK
python tools/doctor.py --check      # какие детекторы доступны
```

Подробности по любому прогону лежат в `<папка-прогона>/scan.log`.

## Частые вопросы

| Симптом | Причина и решение |
|---|---|
| `python: command not found` на Linux/macOS | используйте `python3` вместо `python` |
| `0 findings`, хотя проект явно неидеален | почти все детекторы не установлены. Откройте `scan.log`: там `not installed — skip`. Запустите `python tools/doctor.py` |
| Дашборд открывается, но пустой или со старыми данными | не выполнен `render.py` и/или `sync.py` после последнего скана. Повторите оба |
| `state.js not found: …` | сначала `python tools/render.py <прогон>`; `sync.py` принимает **каталог отчётов**, а не папку прогона |
| `dashboard.html not found … Скопируйте tools/dashboard.html` | скопируйте файл в каталог отчётов (`cp` / `copy`) |
| Вкладка **Diff** пустая | `diff.py` нужно запускать **до** `render.py` |
| `маркеры /*STATE-BEGIN*/ … не найдены` | вы подменили `dashboard.html` другим файлом. Скопируйте оригинал из `tools/` заново |
| `.scoutrc parse error` | в файле ошибка JSON; настройки не применились. Проверьте запятые и кавычки |
| `queue: нечего добавлять` | после фильтра ничего не осталось. По умолчанию порог `--severity high`; попробуйте `--severity all` |
| Детектор падает по таймауту | у каждого лимит 120–240 с (виден в `scan.log`). Используйте `--quick` или исключите детектор в `.scoutrc` |
| Шум: сотни одинаковых `I001` | вкладка **По коду** сворачивает их в группу; лимит: `max_findings_per_detector` |
| Сомнительная находка `secrets` | это ключевые слова + regex; проверьте evidence. Заглушку можно переименовать или вынести в тестовые данные |
| `build-adapters.py` пишет `copy … (symlink failed)` | на Windows нет прав на симлинки; создан обычный файл-копия. Это нормально, но после правки `SKILL.md` запускайте скрипт снова |

## Scout что-то изменил в моём проекте?

Сам Scout в проект ничего не пишет: все отчёты идут в каталог `--out`.
Но два нюанса стоит знать:

- Внешние детекторы запускаются **в каталоге проекта** и могут оставить свои кэши
  (`.mypy_cache`, `.ruff_cache`, `.pytest_cache`, `__pycache__`). Обычно они уже в
  `.gitignore` Python-проектов; проверьте `git status` после скана.
- Детектор `pytest-failed` **запускает тесты вашего проекта**, а значит выполняется
  ваш код со всеми его побочными эффектами. Для непроверенных чужих проектов
  используйте `--quick` (он пропускает `pytest-failed` и `pip-audit`).
